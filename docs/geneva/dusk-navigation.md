# Dusk city and navigation sidebar

The approved architectural baseline bedda3d is retained: no new buildings, allocation, colours, facade layout, shadows or source identities. The main city is fixed to the existing oblique angle and dusk lighting; resolution and full geometry are mandatory rather than user presets. Rendering targets 3x CSS pixels on a 1x display, up to 4x with native DPR, constrained to 12 million pixels and WebGL's maximum renderbuffer/texture dimension. This is a practical GPU limit, not an assertion that every GPU can sustain it. No adaptive geometry selection in the public UI; the LOD implementation is retained internally. Dusk is set before first frame, including civic window emission.

The old permanently reserved inspector column is replaced by a collapsed-by-default right overlay sidebar. Explore toggles it, Enlarge/Reduce changes width, and the left edge is pointer- and keyboard-resizable. Sidebar width never changes the canvas width. Selection does not force it open; search shortcut opens it. Mathematical inspection, evidence, research and history stay available. Only oblique 3D and a flat navigation map remain. The map keeps pan/zoom, has an explicit City 3D button, and clicking a source building or station enters oblique focused there; double-clicking non-source map space enters at that location. Overview resets the current camera without changing views. M switches map/city, I toggles sidebar. Mobile overlay clamps to viewport width.

Browser CI verifies dusk/full/quality at launch, sidebar collapse and enlargement without shrinking canvas, keyboard resize, map entry and existing declaration/research/deep-link checks. No actual visual/device acceptance until hosted run finishes. Higher resolution increases framebuffer cost; no performance guarantees.
