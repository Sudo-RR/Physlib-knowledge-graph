# Geneva browser regression and contributor accessibility

Issues #63, #47, #29, #54. The published bundle is now gated by a headless Chromium software-WebGL smoke test against the actual packaged source snapshot. It checks rendering rather than relying on successful JS bundling, verifies idle draw suppression, source selection, per-file kind/name filters, channel controls, keyboard pan, dusk, flat map, deep links, exact module navigation and mobile width. Fixed screenshots and metrics (revision, draw calls, triangles, idle draw count, page errors) are uploaded even on failure. This is not a hardware FPS benchmark, pixel-diff baseline, screen-reader audit, or complete interaction suite. Browser installation/test failure blocks new publication and leaves last deployed snapshot intact. No dependency on the failed Lean extraction pilot.

The renderer keeps a lightweight animation callback but submits draw calls only when animation, view, focus, quality, size, dependencies or lighting change; skips hidden tabs and hidden 3D view. Quality presets cap device pixel ratio at 1/1.5/2, not geometry LOD. Keyboard controls apply only when the canvas is focused and don't hijack typing. The new per-file browser uses revision-pinned lexical command records; no statement/qualified-name/proof claims, and missing records explicitly mean incomplete coverage. Filter by kind and recorded name, paginate, exact source link. No native review overlays or upstream website changes yet.

Reproduce after npm ci, generating actual data, building the city and npm run package:site: npm install --no-save --package-lock=false playwright@1.56.1; npx playwright install chromium; node scripts/smoke-geneva-browser.mjs. Evidence is under dist/browser-evidence. Device QA and full visual acceptance stay open.
